# Оптимизации в broken-app


Исходный код содержал намеренно неэффективные алгоритмы и некоторые проблемы.  
Оптимизации проводились в два этапа: сначала исправление багов (UB, утечки, логика), затем улучшение производительности.

## 1. Алгоритмическая оптимизация

### 1.1. Числа Фибоначчи (`slow_fib`)

**Было:** рекурсивная реализация с экспоненциальной сложностью `O(2ⁿ)`.

```rust
fn slow_fib(n: u64) -> u64 {
    match n {
        0 => 0,
        1 => 1,
        _ => slow_fib(n - 1) + slow_fib(n - 2),
    }
}
```

**Стало:** итеративная реализация с линейной сложностью `O(n)`.

```rust
fn slow_fib(n: u64) -> u64 {
    if n <= 1 {
        return n;
    }

    let (mut a, mut b) = (0, 1);

    for _ in 2..=n {
        let next = a + b;
        a = b;
        b = next;
    }

    b
}
```

**Результат:** для `n=32` время сократилось с `3.7 мс` до `83 нс` (ускорение ≈ `44 000x`).

### 1.2. Дедупликация (`slow_dedup`)

**Было:** двойной цикл – проверка наличия элемента в `Vec` через линейный поиск, затем вставка и сортировка на каждой итерации. Сложность `O(n²)`.

```rust
for &v in values {
    if !out.contains(&v) {
        out.push(v);
    }
    out.sort_unstable();
}
```

**Стало:** использование `HashSet` для проверки уникальности за `O(1)` (амортизированно), заранее выделена ёмкость, сортировка один раз в конце.

```rust
use std::collections::HashSet;

let mut seen = HashSet::with_capacity(values.len());
let mut out = Vec::with_capacity(values.len());

for &v in values {
    if seen.insert(v) {
        out.push(v);
    }
}

out.sort_unstable();
```

**Результат:** для `5000` элементов время снизилось с `1.8 мс` до `180 мкс` (ускорение ≈ `10x`).

## 2. Микрооптимизации

### 2.1. Предварительное выделение памяти

- В `slow_dedup` добавлен `Vec::with_capacity(values.len())`, чтобы избежать повторных реаллокаций.
- В `leak_buffer` после исправления утечки память выделяется один раз, затем освобождается.

### 2.2. Замена циклов итераторами

- `sum_even` переписан через итераторы (`filter().sum()`), что устранило `unsafe`-доступ и улучшило читаемость.
- В `normalize` вместо `replace(' ', "")` использован `split_whitespace()`, который удаляет все виды пробелов (включая табуляции).

## 3. Исправления, повлиявшие на корректность (не оптимизации)

- Отказ от `unsafe`: все небезопасные блоки удалены или заменены безопасными аналогами.
- Устранение data race: глобальная переменная заменена на `AtomicU64`.
- Исправление логики `average_positive`: теперь учитываются только положительные числа.
- Регрессионные тесты добавлены в `tests/integration.rs` для всех исправленных кейсов.

## 4. Сравнение бенчмарков (baseline)

| Тест | До (среднее) | После (среднее) | Ускорение |
|------|--------------|-----------------|-----------|
| `slow_fib` | 3.72 ms | 83 ns | 44 819x |
| `slow_dedup` | 1.78 ms | 178 µs | 10x |
| `sum_even` | 6.2 µs | 6.1 µs | ~1x |


Оптимизации дали прирост производительности на cpu-bounded функциях за счёт смены алгоритмов. Микрооптимизации (выделение памяти, итераторы) добавили небольшой доп эффект.
