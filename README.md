# broken-app – поиск ошибок и оптимизация

## Описание

Проект содержит намеренно сломанный код (UB, утечки, гонки данных, медленные алгоритмы).  
Задача – починить broken-app, подтвердить отсутствие UB и ускорить критичные участки.

## Требования

- Rust 1.70+ (stable)
- Nightly Rust (для Miri и AddressSanitizer) – опционально

## Сборка и тестирование

```bash
cargo build
cargo test          # все тесты должны проходить
cargo bench         # baseline бенчмарки
```

## Дополнительные инструменты

### Miri (поиск UB)

```bash
cargo +nightly miri test --target aarch64-apple-darwin
```

### AddressSanitizer (утечки и ошибки памяти)

```bash
RUSTFLAGS="-Zsanitizer=address" cargo +nightly test --target aarch64-apple-darwin
```

## Исправленные баги

| Баг | Было | Стало |
|------|------|--------|
| `sum_even` – выход за границы (off-by-one) | `get_unchecked` на `0..=len` | безопасный итератор `filter().sum()` |
| `leak_buffer` – утечка памяти | `Box::into_raw` без освобождения | вызов `Box::from_raw` после подсчёта |
| `race_increment` – гонка данных | `static mut COUNTER` без синхронизации | `AtomicU64` с `Ordering::SeqCst` |
| `average_positive` – логическая ошибка | усреднение по всем элементам (включая отрицательные) | фильтрация положительных чисел |
| `normalize` – не удаляла табуляции | только `replace(' ', "")` | `split_whitespace().collect()` |

## Оптимизации

### 1. Алгоритмическая оптимизация

- `slow_fib`: заменена экспоненциальная рекурсия `O(2ⁿ)` на итеративный алгоритм `O(n)`.
- `slow_dedup`: заменён квадратичный поиск `O(n²)` на линейный через `HashSet` `O(n)`.

### 2. Микрооптимизация

- Убраны лишние аллокации в `slow_dedup`: предварительное выделение ёмкости `Vec::with_capacity`.
- В `leak_buffer` прямой проход по указателю заменён на итератор (после исправления утечки – уже безопасно).

## Бенчмарки (до и после)

Замеры для `n=32` (`fib`) и `5000` элементов (`dedup`), выполнены на baseline-бенчмарке.

| Функция | До (медленно) | После (быстро) | Ускорение |
|----------|---------------|----------------|-----------|
| `slow_fib` | ~3.7 мс | ~83 нс | ~44 000x |
| `slow_dedup` | ~1.8 мс | ~180 мкс | ~10x |
| `sum_even` | ~6 мкс | ~6 мкс | без изменений |

## Профилирование

Из-за короткого времени работы демо-приложения профилировщик `sample` не зафиксировал пользовательские функции.

Основное узкое место было визуально определено до оптимизации: экспоненциальный `slow_fib` и квадратичный `slow_dedup`.

После замены алгоритмов нагрузка стала незначительной.

## Подробности по оптимизациям

1. **Алгоритмическая**: замена экспоненциального Фибоначчи (O(2ⁿ)) на итеративный O(n).
   - Ускорение: с ~3.7 мс до <100 нс для n=32.

2. **Микрооптимизация**: замена квадратичной дедупликации (O(n²)) на линейную через `HashSet`.
   - Ускорение: с ~1.8 мс до ~180 мкс для 5000 элементов.

**Дополнительно исправлены**:
- Off-by-one в `sum_even` (заменён на безопасный итератор).
- Утечка памяти в `leak_buffer` (добавлен `Box::from_raw`).
- Гонка данных в `race_increment` (использован `AtomicU64`).
- Логическая ошибка в `average_positive` (фильтрация положительных).
- Улучшена нормализация строк (теперь удаляет все пробелы).
